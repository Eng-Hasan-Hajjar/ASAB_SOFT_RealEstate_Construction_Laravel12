# عصب سوفت | ASAB SOFT — Real Estate & Operations V3

**Laravel 12 + MySQL + Blade/HTML/CSS/Vanilla JavaScript — Arabic RTL**

منصة تشغيل متعددة الشركات لإدارة العقارات والوحدات والمستأجرين والإيجارات والفواتير والتحصيل النقدي والبنكي والحجوزات والصيانة والمقاولات والفرص التجارية، مع موقع عقاري عام ومساعد محلي قائم على قواعد وبيانات معتمدة. تستهدف السعودية والبحرين، مع فصل شركة عن أخرى في قاعدة البيانات.

## ما المختلف في V3؟

- إدارة الحسابات النقدية والبنكية والأرصدة الافتتاحية ودفتر حركات مفصل.
- تحصيل الفاتورة وتسجيل القيد النقدي/البنكي **داخل معاملة قاعدة بيانات واحدة**.
- تقرير شهري ويومي ومؤشرات للعقار والوحدة والدخل والمصروف والمتأخرات والتصدير CSV.
- توليد استحقاقات العقود الشهرية للأشهر الكاملة فقط، مع منع تكرار الفاتورة لفترة واحدة.
- سجل حجوزات مبدئية ومؤكدة يمنع التداخل مع العقود النشطة والحجوزات المؤكدة.
- رفع ملفات XLSX أو CSV إلى **منطقة مراجعة مشفّرة**؛ دون ترحيل السجلات غير المؤكدة آلياً.
- الاستمرار في وظائف V2: إنشاء الشركات وحسابات موظفيها، لوحة مالك المنصة ودخول مساحة الشركة، إدارة الوحدات والمستأجرين والعقود والفواتير والصيانة والمقاولات وCRM والموقع العام والمساعد المحلي.

## تشغيل أول مرة على Windows / CMD

1. يتطلب PHP >= 8.2 وComposer وMySQL. إضافة `php_zip` مطلوبة لقراءة ملفات XLSX (ليس لتشغيل الموقع العادي).
2. افتح مجلد المشروع (الذي يحتوي على `artisan`) ثم:

```cmd
composer install --prefer-dist
copy .env.example .env
notepad .env
php artisan key:generate
```

3. أنشئ قاعدة MySQL باسم `asab_realty` أو غيّر `DB_DATABASE` في `.env`، وعدّل بيانات الاتصال.
4. أضف داخل `.env` بيانات مدير المنصة (لا تكتبها مباشرة في CMD):

```dotenv
APP_NAME="ASAB SOFT"
APP_LOCALE=ar
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=asab_realty
DB_USERNAME=root
DB_PASSWORD=
PLATFORM_OWNER_NAME="Owner Name"
PLATFORM_OWNER_EMAIL="YOUR_REAL_EMAIL@example.com"
PLATFORM_OWNER_PASSWORD="CHOOSE_A_UNIQUE_STRONG_PASSWORD_12_PLUS"
DEMO_DATA=false
```

5. نفّذ:

```cmd
php artisan migrate --seed
php artisan storage:link
php artisan serve
```

6. افتح `http://127.0.0.1:8000/login` وسجّل الدخول ببيانات المالك؛ أنشئ شركة ثم اضغط **فتح مساحة الشركة**، أو سجّل الدخول بحساب مديرها.

## التحديث من V2 الموجود لديك

- احتفظ بنسخة من قاعدة البيانات ومجلدي `storage` و`public/storage` وملف `.env`، ولا ترفعه إلى GitHub.
- استخدم حزمة التحديث الصغيرة أو انسخ الملفات الجديدة فوق المشروع الحالي **من دون حذف `vendor` أو `.env`**.
- نفّذ:

```cmd
php artisan optimize:clear
php artisan migrate
php artisan storage:link
php artisan serve
```

> **ممنوع** استخدام `migrate:fresh` على بيانات العملاء لأنه يحذف الجداول. الترحيل V3 إضافي ويحتفظ بجداول V2.

## كيفية تجربة السيناريو المتكامل

1. لوحة مالك المنصة `/platform`: أنشئ شركة سعودية أو بحرينية، ثم افتح مساحة الشركة.
2. أضف مبنى في `/manage/properties`، ثم الوحدات في `/manage/units`، والمستأجر في `/manage/contacts`.
3. أضف حساباً نقدياً وآخر بنكياً من `/finance`، ثم عقداً في `/leases`.
4. انتقل إلى `/billing` لتوليد فواتير الإيجارات الشهرية (يُستثنى أول شهر جزئي وآخر شهر جزئي)، أو أنشئ فاتورة منفردة من `/invoices/create`.
5. سجّل دفعة للفاتورة وحدد حساب التحصيل؛ تظهر في `/finance` وفي `/reports`.
6. أضف مصروف صيانة أو مصروفاً تشغيلياً بالربط مع العقار، ولاحظ الصافي الشهري.
7. اختبر حجوزات الوحدات `/reservations` ومنع تضارب المواعيد.
8. انشر عقاراً ووحداته المتاحة من `/listings` وسيظهر على `/properties` العام.
9. جرّب رفع نسخة من ملف Excel إلى `/imports` **للمعاينة فقط**؛ لن تصبح صفوفه مستأجرين أو دفعات تلقائياً.

## شاشات النظام

| الرابط | الوظيفة |
|---|---|
| `/` و`/properties` | واجهة عروض العقارات والبحث |
| `/platform` | مدير الشركات والسوبر أدمن |
| `/dashboard` | لوحة الشركة |
| `/manage/properties`, `/manage/units` | العقارات والوحدات |
| `/manage/contacts` | المستأجرون والأطراف |
| `/leases`, `/billing`, `/invoices` | العقود والاستحقاقات والفواتير |
| `/finance`, `/reports` | الصندوق والبنوك والتقارير |
| `/reservations` | حجز الوحدات والتعارض |
| `/imports` | معاينة XLSX/CSV مع الصفوف المشفرة |
| `/assistant` | مساعد داخلي محلي محدود النطاق |
| `/manage/projects`, `/manage/expenses`, `/manage/tickets` | المقاولات والمصروفات والصيانة |
| `/listings` | نشر العقارات وإدارة الصور |

## حدود الإصدار واعتبارات مهمة

- **ليس منتجاً جاهزاً للإنتاج دون اختبار:** مصدر الشيفرة مُعد للتجربة، ولم يُتحقق من Composer/MySQL والمتصفح في بيئة المستخدم بعد. يتطلب اختبارات قبول واختبار صلاحيات وأمان وأداء قبل تشغيل بيانات حقيقية.
- لا يحتوي المشروع على بيانات العميل المرفوعة ولا على معلومات مستأجرين حقيقية. **لا تنشر ملفات العملاء في مستودع عام**.
- ملفات Excel التي دُرست عددها **14** وبداخلها **398 ورقة عمل** (12 ملف عقارات وملفا دخل شهري). بياناتها تتضمن تواريخ وسجلات مكررة وأخطاء صيغ. الرفع يحفظ بيانات المراجعة مشفرة فقط، ويجب مطابقة الصفوف قبل الترحيل النهائي.
- تحويلات النقد والبنك ليست إيراداً؛ التأمين المسترد ليس ربحاً؛ المدفوعات داخل الفواتير تسجَّل في الدفتر، بينما مصروفات المشاريع المنفصلة تحتاج مطابقة مع حركات الصندوق والبنك لتجنب التكرار.
- اختيار `DEMO_DATA=true` ينشئ بيانات خيالية فقط. لا تستخدمها في تشغيل فعلي.
- مساعد `/assistant` لا يستدعي LLM ولا ينفّذ وعود ذكاء اصطناعي توليدي؛ يتعامل مع قواعد وبيانات محددة. ربط n8n وWhatsApp API مرحلة مستقلة تحتاج موافقات وأمن وتكاليف تشغيل.
- لا يوجد تكامل رسمي مع إيجار أو ZATCA أو أنظمة حجز حكومية؛ الفواتير والتسجيلات داخلية وليست فواتير ضريبية معتمدة تلقائياً.
- حسابات السعودية والبحرين منفصلة بعملة الشركة (SAR/BHD) بدقة ثلاث منازل في قاعدة البيانات، وعرض العملة حسب الدولة.

## سجلات البيانات والأمن

- عزل البيانات بـ `company_id` في جميع العمليات التشغيلية وفحص علاقات السجلات داخل مساحة الشركة.
- أدوار `super_admin`, `company_admin`, `manager`, `accountant`, `agent`, `viewer`.
- جلسة مالك المنصة تستطيع دخول مساحة شركة مع تسجيل أثر العملية والعودة.
- `APP_KEY` لتشفير صفوف الاستيراد؛ احتفظ بنسخة احتياطية آمنة منه.
- سجلات الاستيراد لا تُطبّق تلقائياً؛ أعد مواءمتها مع العقارات والوحدات والحسابات بعد تسوية البيانات القديمة.
