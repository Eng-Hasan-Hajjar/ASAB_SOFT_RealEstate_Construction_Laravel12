# عصب سوفت — حزمة استيراد بيانات العميل العقارية الفعلية (Laravel 12)

**الغرض:** نقل بيانات ملفات Excel الأربعة عشر إلى جداول العمل الفعلية، بما فيها العقارات والوحدات وجهات الاتصال ومسودات العقود القابلة للتفسير، مع شاشتين للتاريخ الإيجاري والنقدي/البنكي. نحتفظ أيضاً بنسخة مشفّرة من كل صف مصدر لمراجعته.

**مهم:** الحزمة لا تُحوّل القيم التاريخية غير المُراجعة إلى إيرادات أو ديون أو أرصدة معتمدة. لا تتصل بواجهات إيجار أو البنوك أو منصات ضريبية.

## 1. محتوى التسليم

- `ASAB_SOFT_REAL_DATA_CODE_ONLY.zip`: ملفات PHP والواجهات والهجرة والتعليمات، **بدون بيانات العميل**، ويمكن رفعها إلى مستودع الشيفرة بعد مراجعتها.
- `ASAB_SOFT_PRIVATE_EXCEL_SOURCE_DATA.zip`: ملف `manifest.json` و14 ملفاً مضغوطاً `source_NN.json.gz`، يحتوي سجلات حقيقية وأسماء وأرقام اتصال. **لا ترفعه إلى GitHub، ولا تنشره على الإنترنت، ولا تضعه تحت `public/`**.

التحديث يشمل:
- خدمة `app/Services/AsabActualExcelImporter.php`
- أمر `asab:import-actual`
- سيدر `AsabActualClientDataSeeder` لمن يريد استخدام `db:seed --class=...`
- Migration `2026_11_13_000004_create_asab_legacy_operational_history.php`
- شاشتين `/asab/history/rentals` و`/asab/history/finance`
- روابط جديدة في القائمة ولوحة المؤشرات، مع إصلاح تنسيق ملف Dashboard Blade السابق.

## 2. التثبيت على نسختك الحالية في Windows

أوقف الخادم (`Ctrl+C`) أولاً، وخذ نسخة احتياطية من قاعدة `asab_realty` وملف `.env` ومجلد `storage/`، ثم:

1. فك **حزمة الكود** في المجلد الذي يحتوي `artisan` و`composer.json` ووافق على استبدال الملفات المطابقة.
2. فك **حزمة البيانات الخاصة** في المجلد نفسه: يجب أن يصبح المسار:
   `storage/app/asab-private-import/manifest.json` مع `source_01.json.gz` إلى `source_14.json.gz`.
3. **لا تحذف** `vendor` أو `.env`، ولا تنسخ أي كلمة مرور جديدة إلى ملف التعليمات.
4. نفّذ الأوامر:

```cmd
php artisan optimize:clear
php artisan migrate
php artisan asab:import-actual --company=sss --dry-run
```

`sss` هو `slug` الشركة الظاهرة في لقطة قاعدة بياناتك السابقة (حساب مدير الشركة الموجود). **إذا تريد الاستيراد لشركة أخرى، استبدل `sss` بالـ slug الصحيح الموجود فعلاً في جدول `companies`.**

إذا أعطى الفحص النتائج المتوقعة وتأكدت أن الشركة المختارة صحيحة، نفّذ:

```cmd
php artisan asab:import-actual --company=sss
php artisan optimize:clear
php artisan asab:seed-audit --slug=sss
php artisan serve
```

**لا تستخدم** `migrate:fresh` أو `migrate:refresh` أو `db:wipe` أو `db:seed` العام على قاعدة فيها بيانات عملاء. لا حاجة لإنشاء super_admin أو مدير شركة جديد، ويجري الاستيراد إلى الشركة الموجودة بالفعل.

## 3. أين ستجد البيانات؟

- `/manage/properties` — ملفات العقارات الاثنا عشر (قد يوجد غيرها سابقاً).
- `/manage/units` — 391 وحدة مع رمز الوحدة الأصلي، بحالة **غير مؤكدة** ومخفية عن الموقع العام.
- `/manage/contacts` — المستأجرون والأسماء المستخرجة (مع احتمال تكرارات المصدر).
- `/leases` — ما أمكن تفسيره بطريقة آمنة كمسودات فقط (وليس عقوداً نشطة).
- `/asab/history/rentals` — أسطر الفترات التاريخية المرتبطة بالعقارات والوحدات.
- `/asab/history/finance` — دفتر الدخل النقدي والبنكي وبعض المصروفات التاريخية، **غير معتمد**.
- `/imports` — جميع صفوف المصدر، مشفرة في قاعدة البيانات، مع مرجع الورقة والصف.

> لا يظهر المستورد على الموقع العام `/properties` حتى يتم نشر العقار والوحدة صراحة من إدارة الإعلانات. هذه حماية مقصودة لمعلومات العميل وأسعار الإيجارات غير المراجعة.

## 5. قواعد سلامة البيانات

- لا يُفترض أن القيمة الموجودة في خانة «المبلغ» هي «إيجار شهري حالي»؛ لذلك لا تُنسخ آلياً إلى `units.monthly_rent`.
- لا تُحدد حالة الوحدة «متاحة» أو «مشغولة» من آخر اسم في Excel دون التأكد؛ الوحدة المستوردة تبدأ `inactive` وتظهر في الإدارة.
- تُحفظ التواريخ الهجرية كما وردت نصياً، ولا يُختلق لها تحويل ميلادي.
- تُحوّل أرقام Excel التسلسلية ذات المدى المعروف إلى تاريخ ميلادي عند إمكانية ذلك، مع إبقاء الأصل.
- النص المالي في ملفات أكتوبر ونوفمبر قد يحوي مجاميع وأرصدة جانبية؛ يتم استيراد الحركات التي أمكن تمييز حقولها فقط إلى شاشة التاريخ، وبقية صفوف المال محفوظة في `/imports`.
- كل السجلات التاريخية تحمل مرجع الملف والورقة ورقم الصف ومؤشر «بحاجة إلى مراجعة».
- لا يوجد إنشاء تلقائي لـ `invoices` أو `payments` أو `ledger_entries` من هذه المصادر، تفادياً لتضخيم التحصيل الحقيقي أو احتساب المبالغ مرتين.
- لا تُحدّث بيانات سجل أدخله موظف يدوياً بعد الاستيراد، بل تستخدم قواعد `firstOrCreate`/`insertOrIgnore`.
- بيانات الاستيراد محمية بفصل `company_id` في جميع عمليات القراءة والكتابة، وبصلاحيات الجلسة.

## 6. بديل السيدر التقليدي

يمكن استخدام السيدر بدلاً من الأمر إذا ضبطت داخل `.env` الـ slug الصحيح:

```dotenv
ASAB_CLIENT_COMPANY_SLUG=sss
```

ثم:

```cmd
php artisan db:seed --class=AsabActualClientDataSeeder
```

**لا تشغّل** `AsabInitializeAccountsSeeder` لإعادة إنشاء حسابات موجودة؛ السيدر الجديد مستقل عنه.

## 7. الاستعلامات الآمنة للتحقق في phpMyAdmin

نفّذ للاستعلام عن عدد السجلات (لا يعرض بيانات شخصية):

```sql
SELECT c.id, c.slug, c.name,
       (SELECT COUNT(*) FROM properties p WHERE p.company_id=c.id) AS properties,
       (SELECT COUNT(*) FROM units u WHERE u.company_id=c.id) AS units,
       (SELECT COUNT(*) FROM contacts t WHERE t.company_id=c.id) AS contacts,
       (SELECT COUNT(*) FROM asab_rental_history r WHERE r.company_id=c.id) AS rental_history,
       (SELECT COUNT(*) FROM asab_financial_history f WHERE f.company_id=c.id) AS financial_history
FROM companies c WHERE c.slug='sss';
```

إذا كانت هناك فروق، لا تنفذ مسحاً للجداول؛ أرسل فقط آخر سطور الخطأ وعدد السجلات، وسنحدد الملف والورقة المتسببين بالمشكلة.

## 8. حماية البيانات واعتبارات الإطلاق

- لا ترفع ZIP الخاص ببيانات العميل إلى GitHub أو خدمات عامة. يحتوي الأرشيف المضغوط على بيانات حقيقية **غير مشفرة قبل الاستيراد**.
- تأكد أن `.gitignore` تحت `storage/app/asab-private-import/` موجود وفيه `*` حتى لا تتسرب ملفات المصدر.
- شاشات السجلات التاريخية داخل منطقة الدخول، والمعلومات المالية مقصورة على أدوار الشركة التي يحق لها قراءتها.
- بعد الاستيراد، صفوف المصدر الأصلية مخزنة بتشفير Laravel المرتبط بـ `APP_KEY`؛ احفظ نسخاً احتياطية محمية له ولا تقم بتغييره عشوائياً.
- تجنب استخدام قاعدة بيانات الإنتاج مباشرة قبل التأكد من صحة الأرقام وموافقة العميل على استيراد معلوماته.
- اختبر يدوياً واحداً من كل نوع: شقة، محل، عقد تاريخي، تحصيل نقدي، دخل بنكي، مصروف نقدي، وفصل شركة أخرى.

**التوافق المستهدف:** Laravel 12 / PHP 8.2+ / MySQL 8 أو MariaDB المتوافقة. فُحصت الصياغة والبيانات المصدرية؛ التنفيذ الكامل يحتاج تشغيل الأمر على جهازك.
